# 08. ETL / ELT & Data Vault Loading Patterns

> Раздел образовательной программы Data Vault 2.0. Модуль 8 из 12.

## Назначение модуля

Поток загрузки связывает источник и Raw Vault через извлечение, staging, дедупликацию и контроль идемпотентности. Надёжность проверяется не только в нормальном режиме, но и при повторных запусках, опоздавших данных и изменениях схем.

## Банковский пример

Первичная полная загрузка клиентов, затем log-based CDC; staging нормализует ключи, а Raw Vault вставляет только новые идентичности и версии.

## Схема потока данных

```mermaid
flowchart LR
    S[Source Systems] --> ST[Landing / Staging]
    ST --> H[Raw Vault: Hubs / Links / Satellites]
    H --> B[Business Vault: PIT / Bridge]
    B --> M[Dimensional Marts]
    M --> BI[BI / Analytics]
```

### 4. Change Data Capture (CDC)

**Определение и принцип.** CDC обнаруживает вставки, изменения и удаления в транзакционном источнике. Способы: чтение транзакционного журнала, триггеры, timestamp-поля и сравнение снимков; их полнота и нагрузка различаются.

**Практическая интерпретация.** Debezium читает изменения поддерживаемой СУБД и публикует события в поток передачи данных.

**Ограничения и проверки.** Необходимо учитывать начальный snapshot, порядок сообщений, commit offsets, tombstones и повторную доставку.

### 19. Idempotency

**Определение и принцип.** Идемпотентность означает, что повторное выполнение операции с тем же входом не создаёт нового логического эффекта. В пайплайнах это достигается ключами дедупликации, транзакциями, upsert или проверкой существования версии.

**Практическая интерпретация.** Повторная загрузка одного CSV после сбоя не должна удваивать Hub и Satellite.

**Ограничения и проверки.** Проверяйте результат повторного запуска, а не только успешное завершение первого.

## Технический пример

```sql
-- Пример безопасной дедупликации входного batch по event_id
WITH ranked AS (
 SELECT *, row_number() OVER (
   PARTITION BY event_id ORDER BY source_updated_at DESC, ingest_dts DESC
 ) AS rn
 FROM staging.payment_event_batch
)
SELECT * FROM ranked WHERE rn = 1;
-- Нужен стабильный tie-breaker при полном совпадении сортировки.
```
