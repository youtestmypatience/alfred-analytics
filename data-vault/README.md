# Alfred Analytics — Data Vault Knowledge Base

Статический образовательный сайт по 12 модулям Data Vault 2.0 и папка Markdown-конспектов.

## Структура

- `site/index.html` — главная страница.
- `site/module-01.html` … `site/module-12.html` — отдельные страницы модулей.
- `site/assets/` — оформление, JavaScript и данные навигации.
- `knowledge/` — независимые Markdown-файлы для Obsidian.

## Запуск

Откройте `site/index.html` в браузере. Для проверки через локальный сервер: `cd site && python3 -m http.server 8000` и перейдите на `http://localhost:8000`.

## Публикация GitHub Pages

Скопируйте **содержимое** папки `site` в корень репозитория GitHub Pages и включите Pages для ветки, содержащей эти файлы.

## Прогресс

По умолчанию прогресс сохраняется в гостевом `localStorage`. При входе в аккаунт используется отдельный локальный кеш, привязанный к Supabase User ID; изменения синхронизируются с таблицей `study_progress`. Экспорт/импорт JSON сохранён. В гостевом режиме регистрация не обязательна.

## Подключение регистрации и синхронизации

1. Создайте проект Supabase и включите Email provider в Authentication.
2. Выполните файл `supabase/001_progress.sql` через Supabase SQL Editor: он создаёт таблицу и политики Row Level Security, позволяющие пользователю читать и обновлять **только собственный прогресс**.
3. Укажите **Supabase Project URL** и **Publishable Key** в `site/assets/supabase-config.js`. Эти два значения предназначены для публичного frontend. Никогда не вставляйте `service_role` или secret key.
4. В Supabase Authentication → URL Configuration настройте Site URL и Redirect URLs на адрес GitHub Pages сайта.
5. Выложите файлы на HTTPS. После активации конфигурации появится работающая форма email/пароль. При создании аккаунта может потребоваться подтверждение email.

Гостевая часть не обращается к Supabase и работает даже без подключения сервиса. Пока в `supabase-config.js` нет параметров, форма честно сообщает, что облако не настроено, и не предлагает фиктивную регистрацию.

**Конфликты:** первоначальная версия сохраняет весь прогресс пользователя одним JSON-объектом (last-write-wins). При одновременном редактировании на двух устройствах или длительной работе offline есть риск перезаписи более свежего состояния. Для надёжной конкурентной синхронизации в следующем релизе нужно перейти на таблицу отметок по каждому разделу со временем изменения и серверным merge. В первой версии используйте JSON-экспорт как резервную копию.


## Ограничения материалов

В каждом модуле присутствуют все темы исходного roadmap, учебные объяснения, пример и ссылки. Это первая редакция базы знаний: особенно специализированные паттерны требуют последующей углублённой проработки и проверки по документации версии используемых пакетов. Реальные банковские данные не использованы.
