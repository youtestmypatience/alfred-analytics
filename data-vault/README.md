# Alfred Analytics — Data Vault Knowledge Base

Статический образовательный сайт по 12 модулям Data Vault 2.0 и папка Markdown-конспектов.

## Структура

- `site/index.html` — главная страница.
- `site/module-01.html` … `site/module-12.html` — отдельные страницы модулей.
- `site/assets/` — оформление, JavaScript и данные навигации.
- `knowledge/` — независимые Markdown-файлы для Obsidian.

## Запуск

Откройте `site/index.html` в браузере. Для проверки через локальный сервер: `cd site && python3 -m http.server 8000` и перейдите на `http://localhost:8000`.

## Публикация GitHub Pages

Скопируйте **содержимое** папки `site` в корень репозитория GitHub Pages и включите Pages для ветки, содержащей эти файлы.

## Прогресс

По умолчанию прогресс сохраняется в гостевом `localStorage`. При входе в аккаунт используется отдельный локальный кеш, привязанный к Supabase User ID; изменения синхронизируются с таблицей `study_progress`. Экспорт/импорт JSON сохранён. В гостевом режиме регистрация не обязательна.

## Подключение регистрации и синхронизации

Сайт поддерживает необязательные аккаунты с email/паролем и полностью автономный гостевой режим. Для активации нужна собственная организация/проект Supabase.

1. Создайте проект Supabase, если его ещё нет. Проверьте тариф и регион перед созданием.
2. Выполните SQL `supabase/001_progress.sql`: он создаёт две таблицы (`study_topic_progress` и `study_reading_progress`) с RLS. Каждая тема хранится отдельно, поэтому работа над разными темами на двух устройствах не перезаписывает чужие изменения. Для одного и того же раздела при одновременной правке действует последний успешно обработанный сервером запрос.
3. Укажите только публичный URL и publishable key в `site/assets/supabase-config.js`; запрещено вставлять секретный ключ или `service_role`.
4. В Supabase Auth включите Email provider и подтверждение адреса электронной почты. Для production укажите собственный SMTP, т.к. встроенная рассылка ограничена.
5. Настройте `Site URL` и разрешённый `Redirect URL`: `https://youtestmypatience.github.io/alfred-analytics/data-vault/` и адреса HTML-страниц по необходимости. EmailRedirectTo в коде указывает на точную страницу, где инициирована регистрация.
6. Проверьте в Data API, что таблицы доступны роли `authenticated`, а `anon` не может читать/менять ни один ряд. Для новых проектов Supabase 2026 публикация таблиц через Data API может потребовать явного включения экспонирования схемы.
7. Тестируйте на двух независимых браузерах и двух аккаунтах: отдельные изменения должны синхронизироваться, доступ к чужому прогрессу должен блокироваться RLS.

### Синхронизация

- У гостя данные хранятся только в `localStorage`.
- У зарегистрированного пользователя отдельное локальное хранилище по User ID, плюс облачные таблицы.
- После изменения отметки новая запись для **конкретной темы** ставится в локальную очередь. Неудачные запросы оставляют очередь на устройстве, повторный запрос происходит при возобновлении подключения.
- При входе локальные ожидающие изменения накладываются поверх полученных из облака данных. После успешной отправки очередь очищается, и облако перечитывается.
- Импорт гостевого прогресса доступен по выбору после входа и в меню аккаунта. Гостевые данные не удаляются.
- Полностью одновременное изменение **одной и той же** темы с двух устройств решается по порядку записи на сервере. Это не строгая CRDT-синхронизация.
- Экспорт/импорт JSON остаётся резервным способом переноса.

### Текущий статус

Если `site/assets/supabase-config.js` не заполнен, регистрация неактивна, и сайт показывает соответствующее сообщение. Нельзя считать облачную авторизацию работающей до создания базы, настройки Email/redirect и проверки на двух устройствах.

## Ограничения материалов

В каждом модуле присутствуют все темы исходного roadmap, учебные объяснения, пример и ссылки. Это первая редакция базы знаний: особенно специализированные паттерны требуют последующей углублённой проработки и проверки по документации версии используемых пакетов. Реальные банковские данные не использованы.
